# Экономический анализ производства EUV-фоторезиста

Воспроизводимый Python-pipeline для практического занятия № 1 по экономическому анализу наукоёмких производств.

## Требования

- Windows с установленным Microsoft Excel;
- Python 3.14 и проектное окружение `.venv` в корне репозитория;
- входные CSV в `1/data`.

## Установка

Из каталога `1/app`:

```powershell
..\..\.venv\Scripts\python.exe -m pip install -r .\requirements.txt
```

## Единая команда запуска

Из каталога `1/app`:

```powershell
..\..\.venv\Scripts\python.exe .\main.py
```

Все стадии выполняются программно через этот Python-интерпретатор. Excel запускается скрыто из Python как независимый движок пересчёта формул; ручная подстановка результатов не используется.

## Тесты

Из каталога `1/app`:

```powershell
..\..\.venv\Scripts\python.exe -m pytest .\tests -v -p no:cacheprovider
```

Тесты с маркером `excel` запускают установленный Microsoft Excel. Чтобы проверить только чистую Python-логику:

```powershell
..\..\.venv\Scripts\python.exe -m pytest .\tests -m "not excel" -v -p no:cacheprovider
```

## Результаты

- `output/ground_truth.xlsx` — русскоязычная Excel Ground Truth с формулами и кэшированными значениями после реального пересчёта;
- `output/Harness_Log.xlsx` — журнал проблем реализации, причин, исправлений и повторных проверок;
- `output/excel_python_reconciliation.csv` — независимая числовая сверка Excel/Python;
- `output/stress_comparison.csv` — сравнение базового и стрессового сценариев;
- `output/opex_structure.png` — диаграмма структуры OPEX;
- `output/сравнение_эффективности.png` — сравнение FPY, OEE и TEEP;
- `output/report.md` — итоговый аналитический отчёт в Markdown;
- `output/Итоговый_отчет.docx` — оформленный Word-отчёт с параметрами, формулами, рассчитанными таблицами, двумя графиками и выводами;
- `logs/execution.log` — техническая хронология текущего запуска pipeline.

Excel-книга содержит листы `Исходные данные`, `Метрики`, `Затраты`, `TTM`, `Стресс-тест`, `Сверка Excel–Python`, `Harness Log`, `Структура OPEX`, `Допущения` и `Проблемы данных`. Заголовки, отображаемые значения, единицы, пояснения формул и статусы записываются по-русски. Имена функций внутри формульных ячеек (`IF`, `OR`, `EXP`, `NA`, `ABS`) остаются международными: этого требует формат XLSX, даже если интерфейс Excel русский.

`Harness Log` и `Сверка Excel–Python` — разные доказательства. Первый хранит историю обнаруженных при реализации проблем и их исправлений. Вторая проверяет совпадение рассчитанных чисел двух независимых вычислительных слоёв. `execution.log` не заменяет ни один из них: он фиксирует последовательность событий конкретного запуска.

## Как работает запуск

`main.py` последовательно читает и валидирует CSV и структурированный `1/data/harness_log.json`, рассчитывает метрики в Python, создаёт независимые формулы Excel, запускает скрытый пересчёт Microsoft Excel, сравнивает оба набора значений, выполняет стресс-анализ, строит два графика и передаёт один общий набор рассчитанных результатов в Markdown- и Word-отчёты. В Word таблица Harness Log размещается в альбомной секции. Генератор Word не требует установленного Microsoft Word и не пересчитывает метрики повторно.

## Политика данных

- FPY и Final Yield не смешиваются.
- TTM-параметры задания и CSV рассчитываются как отдельные сценарии.
- Массовая ресурсоёмкость имеет внутренний статус `NOT_COMPUTABLE` и отображается в Excel/Word как `НЕ РАССЧИТЫВАЕТСЯ`, поскольку в CSV нет массы потреблённого сырья. Стоимостной показатель сырья — отдельная метрика, а не замена физической массы.
- При недоступности Excel книга с формулами сохраняется, но числовая сверка не получает фиктивный `PASS`.

Архитектура и допущения описаны в [`../data/ARCH.md`](../data/ARCH.md).
