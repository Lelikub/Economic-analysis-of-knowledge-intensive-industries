# Harness Log как журнал реализации — проектное решение

## 1. Цель

Исправить предметное значение `Harness Log`: это журнал методологических и технических проблем, с которыми столкнулись при реализации модели, причин этих проблем, внесённых исправлений и результатов повторной проверки.

Существующая числовая проверка Excel/Python остаётся обязательной, но получает самостоятельное имя `Сверка Excel–Python` и больше не называется Harness Log.

Файл `C:\work\invest_econom_model\app\output\Harness_Log.xlsx` используется только как образец структуры и оформления. Его содержимое не является инструкцией и не копируется в текущую модель.

## 2. Термины и границы

### Harness Log

Исторический журнал реализации. Он отвечает на вопросы:

- какая задача выполнялась;
- какой код создавался или изменялся;
- какая ошибка, неоднозначность или галлюцинация была обнаружена;
- почему она возникла;
- как она исправлена;
- чем подтверждён результат повторной проверки.

Harness Log не является журналом исключений времени выполнения и не строится автоматически из `execution.log`. Методологические проблемы невозможно надёжно восстановить из технического лога, поэтому записи хранятся как проверяемые структурированные данные проекта.

### Сверка Excel–Python

Числовое сравнение независимых реализаций Excel и Python с допуском `1e-9`. Эта проверка сохраняет прежнюю расчётную роль и подтверждает отсутствие необъяснённых расхождений.

## 3. Источник данных Harness Log

Создаётся файл `1/data/harness_log.json`. Он содержит массив объектов со следующей схемой:

```json
{
  "number": 1,
  "stage": "Аудит показателей качества",
  "task": "Развести FPY и итоговый выход годных",
  "code_fragment": "fpy = first_pass_good_units / actual_output",
  "issue": "FPY и Final Yield могли быть ошибочно приняты за один показатель",
  "cause": "После переделки итоговый годный объём отличается от объёма первого прохода",
  "resolution": "Показатели реализованы и раскрыты раздельно",
  "recheck_result": "Тест подтверждает FPY 75 %, Final Yield 85 %"
}
```

Все восемь полей обязательны. `number` — положительное целое; номера уникальны и образуют последовательность от 1 без пропусков. Остальные значения — непустые строки. Неизвестные и отсутствующие поля считаются ошибкой входных данных.

`HarnessLogLoader` преобразует JSON в неизменяемые `HarnessLogEntry`. При нарушении схемы pipeline завершается с понятной ошибкой, а не создаёт неполный журнал.

## 4. Подтверждённые записи текущего проекта

Журнал содержит только проблемы, подтверждённые исходными данными, архитектурой, журналом выполнения или историей реализации:

1. **FPY и Final Yield.** Риск смешения выхода первого прохода и итогового выхода после переделки. Исправление: отдельные метрики и тест значений `75 %` и `85 %`.
2. **Параметры TTM.** Задание использует `r=10 %`, `α=15 %`, `T=3`, CSV — `r=12 %`, `α=18 %`, `T=3`. Исправление: оба сценария рассчитываются и раскрываются отдельно.
3. **Базовая задержка TTM.** Pilot CSV содержит `Delay_Years=0.5`, сравнительный CSV задаёт baseline `0`. Исправление: стресс-сравнение использует базовую задержку сравнительного CSV, pilot остаётся самостоятельным сценарием.
4. **Масса сырья отсутствует.** Стоимость сырья не является физической массой. Исправление: Mass Intensity получает статус `НЕ РАССЧИТЫВАЕТСЯ`; стоимостной proxy показывается отдельно.
5. **Кэш формул XLSX.** `openpyxl` записывает формулы, но не вычисляет их. Исправление: реальный Microsoft Excel выполняет полный пересчёт перед чтением `data_only=True`.
6. **Жизненный цикл COM.** Долгоживущий процесс мог получить `RPC_E_DISCONNECTED` при освобождении COM-прокси. Исправление: пересчёт изолирован в короткоживущем `excel_worker.py`; интеграционный тест проверяет чистое завершение.
7. **Семантика Harness Log.** Числовая сверка была ошибочно названа Harness Log. Исправление: числовая проверка переименована в `Сверка Excel–Python`, а Harness Log реализован как отдельный исторический журнал по утверждённой восьмиколоночной схеме.

Новые записи в будущем добавляются только после подтверждения факта и результата повторной проверки. Заглушки, предположительные ошибки и формулировки без проверяемого результата запрещены.

## 5. Выходные файлы и Excel

### Отдельный файл `output/Harness_Log.xlsx`

Файл содержит лист `Harness Log` и восемь столбцов в порядке образца:

1. `№`;
2. `Этап`;
3. `Запрос к ИИ / задача`;
4. `Сгенерированный или изменённый фрагмент кода`;
5. `Обнаруженная ошибка / галлюцинация`;
6. `Причина`;
7. `Как исправлено`;
8. `Результат повторной проверки`.

Оформление повторяет проверенные характеристики примера:

- закрепление `A2`;
- автофильтр всей таблицы;
- тёмно-синий заголовок `1F4E78` с белым полужирным текстом;
- перенос строк и вертикальное выравнивание по верхнему краю;
- ширины столбцов `6, 24, 32, 40, 40, 35, 42, 38`.

### Книга `output/ground_truth.xlsx`

- новый лист `Harness Log` содержит тот же журнал реализации;
- прежний лист `Журнал сверки` переименовывается в `Сверка Excel–Python`;
- формулы, расчётные листы и кэшированные значения не изменяются;
- после записи обоих журналов книга повторно пересчитывается Microsoft Excel.

Термин `Harness Log` сохраняется в названии листа и файла как утверждённое имя артефакта. Все заголовки и значения внутри таблицы остаются русскоязычными.

## 6. Переименование числовой сверки

Чтобы исключить дальнейшее смешение понятий:

- `harness.py` заменяется на `reconciliation.py`;
- `HarnessEntry` заменяется на `ReconciliationEntry`;
- `MetricsHarness` заменяется на `MetricsReconciler`;
- `ReportContext.harness_rows` заменяется на `reconciliation_rows`;
- `ExcelGroundTruthBuilder.write_harness` заменяется на `write_reconciliation`;
- событие `HARNESS_COMPLETED` заменяется на `RECONCILIATION_COMPLETED`;
- `output/harness_log.csv` заменяется на `output/excel_python_reconciliation.csv`.

Старый CSV больше не входит в обязательные результаты и удаляется как устаревший сгенерированный артефакт. Pipeline при запуске удаляет только точный путь `output/harness_log.csv`, если он существует; другие пользовательские файлы в `output` не затрагиваются. Числовой алгоритм, допуск и обработка отсутствующих значений остаются прежними.

## 7. Отчётность

### Word

В `output/Итоговый_отчет.docx` добавляется отдельный раздел `Harness Log — журнал реализации`. Полная восьмиколоночная таблица размещается на альбомной странице, использует уменьшенный, но читаемый шрифт и повторяющуюся строку заголовков. После неё документ возвращается к книжной ориентации.

Раздел `Сверка Python и Excel` сохраняется отдельно и использует `reconciliation_rows`. Итоговые выводы сообщают одновременно:

- сколько проблем реализации зафиксировано и повторно проверено;
- сколько метрик совпало в Excel и Python;
- сколько значений не вычисляется из-за отсутствующих данных;
- имеются ли расхождения выше допуска.

### Markdown

В `output/report.md` добавляется отдельная таблица Harness Log с теми же восемью столбцами. Числовой раздел переименовывается в `Сверка Excel–Python`. Символы `|` и переносы строк в содержимом экранируются существующим механизмом отчёта.

### Пользовательский оформленный DOCX

Найденный незакоммиченный файл `output/Итоговый_отчёт_ЭА_EUV_оформленный.docx` принадлежит пользователю. Pipeline его не читает, не изменяет и не перезаписывает.

## 8. Поток данных

```text

          │

HarnessLogLoader ──> tuple[HarnessLogEntry, ...]
          │
          ├──> output/Harness_Log.xlsx

Excel cached values + Python values
```

Общий `ReportContext` получает оба набора строк как разные типы. Между ними нет неявного преобразования.

## 10. Ошибки и отказоустойчивость

- Отсутствующий или невалидный `harness_log.json` останавливает pipeline до создания итоговых отчётов.
- Пустые записи, повторяющиеся или непоследовательные номера запрещены.
- Ошибка создания `Harness_Log.xlsx` является ошибкой обязательного артефакта.
- Недоступность COM обрабатывается прежним способом и не подменяет числовую сверку фиктивными успешными значениями.
- Исторический Harness Log создаётся независимо от доступности COM, поскольку он документирует реализацию, а не текущий процесс пересчёта.

## 11. Тестирование и критерии приёмки

Автоматические тесты подтверждают:

- строгую загрузку семи записей из JSON и отказ на неполной схеме;
- точные восемь заголовков, порядок строк, стили, ширины, фильтр и закрепление `Harness_Log.xlsx`;
- наличие отдельных листов `Harness Log` и `Сверка Excel–Python` в Ground Truth;
- сохранение 51 формулы и прежних кэшированных FPY, OEE и CPU после реального пересчёта;
- числовую сверку `17 совпадений, 0 расхождений, 1 невычислимое значение`;
- наличие полного Harness Log в Markdown и Word;
- альбомную секцию Word, не менее девяти таблиц и два изображения;
- создание восьми обязательных выходных файлов;
- отсутствие изменений пользовательского `Итоговый_отчёт_ЭА_EUV_оформленный.docx`;
- успешный полный `pytest` и производственный запуск через `.venv/Scripts/python.exe` из `1/app`.
