## 6. Формулы

Используй математические определения из приложенной лекции.

### 6.1 FPY

```text
FPY = G_fr / N
```

где:

- `G_fr` = количество годной продукции с первого прохода;
- `N` = количество запущенной / обработанной продукции.

Для текущего набора данных необходимо корректно сопоставить:

- `First_Pass_Good_Units`
- `Actual_Output`

Проверь физический смысл такого соответствия перед расчётом.

Также отдельно рассчитай:

```text
Final Yield = Final_Good_Units / Actual_Output
```

Не подменяй FPY итоговым Yield.

---

### 6.2 Availability

```text
A = Actual_Hours / Planned_Hours
```

Обработай случай:

```text
Planned_Hours = 0
```

---

### 6.3 Performance

Согласно лекции:

```text
P =
(Normative Cycle Time × Quantity)
/
Actual Operating Time
```

Если отдельного `Normative Cycle Time` в данных нет, не придумывай его.

Проверь возможность вывести его через:

```text
Normative Cycle Time =
Planned_Hours / Target_Output
```

и затем использовать `Actual_Output`.

То есть потенциально:

```text
Performance =
Normative Cycle Time × Actual_Output / Actual_Hours
```

Но перед применением обязательно:

1. проверь размерность;
2. объясни допущение;
3. зафиксируй его в `Assumptions Log`.

---

### 6.4 Quality

Для OEE:

```text
Q = FPY
```

как указано в лекции.

---

### 6.5 OEE

```text
OEE = A × P × Q
```

Проверить:

```text
0 ≤ OEE ≤ 1
```

при физически корректных исходных данных.

Не округлять промежуточные вычисления.

---

### 6.6 Utilization

```text
Utilization =
Planned_Hours / Calendar_Hours
```

---

### 6.7 TEEP

```text
TEEP =
OEE × Utilization
```

---

### 6.8 Удельная ресурсоёмкость

Используй общий принцип из лекции:

```text
I(S) = E(S) / Q_product(S)
```

где:

- `E(S)` — суммарное потребление соответствующего ресурса;
- `Q_product(S)` — количество продукции.

Нужно рассчитать предусмотренные заданием:

- массовую;
- энергетическую;
- экономическую

удельную ресурсоёмкость.

**ВАЖНО:**  
Если CSV не содержит достаточных физических данных для корректного расчёта какой-либо ресурсоёмкости, например отсутствует масса потреблённого сырья:

**НЕ придумывай массу.**

Вместо этого:

1. зафиксируй `Data Gap`;
2. объясни, какого параметра не хватает;
3. предложи минимально необходимое дополнительное поле;
4. если возможен proxy-показатель — рассчитай его только отдельно и явно подпиши как `proxy`.

Основной результат нельзя выдавать за физически корректную массовую ресурсоёмкость без достаточных данных.

---

### 6.9 CPU

Используй определение лекции:

```text
CPU =
Total Manufacturing Cost
/
Good Units Produced
```

Полные производственные затраты должны быть построены прозрачно.

Раздели минимум:

```text
Raw Material Cost
+
Energy Cost =
Energy_kWh × Energy_Cost_Rate
+
OPEX Overhead
+
Economic Depreciation
```

Экономическая амортизация оборудования за месяц:

```text
Monthly Depreciation =
Equipment_CAPEX
/
Amortization_Years_Economic
/
12
```

если расчётный период CSV действительно составляет один месяц.

Перед использованием это допущение нужно проверить по `Calendar_Hours` и описанию данных.

```text
Total Manufacturing Cost =
Raw Material Cost
+ Energy Cost
+ OPEX Overhead
+ Monthly Depreciation
```

```text
CPU =
Total Manufacturing Cost
/
Final_Good_Units
```

Проверь физический смысл выбора `Final_Good_Units` в знаменателе.

Не используй FPY-units для CPU автоматически.

## 7. TTM и экономический штраф

Реализуй отдельный `TTMCalculator`.

Формула полной модели из лекции:

```text
L =
1 -
[
1 / (1+r)^Δt
]
×
e^(-αΔt)
×
[(T-Δt)/T]
×
I(Δt)
```

где:

- `r` — ставка дисконтирования;
- `α` — темп ценовой эрозии;
- `T` — рыночный горизонт;
- `Δt` — задержка;
- `I(Δt)` — индикатор открытого рыночного окна.

Обработай крайние случаи:

```text
Δt = 0
Δt >= T
T <= 0
r <= -1
Market_Window_Open = 0
Market_Window_Open = 1
```

Не допускай бессмысленных результатов молча.

1. тариф электроэнергии ×3;
2. FPY снижается до 40%;
3. Delay = 0.5 года.

Не создавай эти значения вручную, если они уже представлены в специальном CSV.

Покажи:

| Metric | Baseline | Stress | Absolute Change | Relative Change | Interpretation |
|---|---:|---:|---:|---:|---|

Минимум:

- FPY
- OEE
- TEEP
- Energy Cost
- Economic Resource Intensity
- CPU
- TTM Penalty

Если показатель не изменяется — это тоже должно отображаться.

## 20. Unit Tests

Помимо трёх тестов из задания добавь минимальный разумный набор автоматических тестов:

Но не усложняй проект чрезмерно ради архитектуры.

## 23. Нельзя

Нельзя:

- вручную подставлять заранее вычисленные итоговые метрики;

- выдавать Python-числа за Excel Ground Truth;
- записывать только готовые числа вместо Excel-формул;
- копировать Python results в Excel и затем сравнивать Excel с теми же Python results;
- замалчивать недостающие данные;
- выдумывать массу сырья;
- смешивать FPY и Final Yield;
- округлять промежуточные расчёты;
- игнорировать размерности;
- подавлять исключения через пустой `except`;
- использовать catch-all exception без логирования;
- смешивать baseline и stress данные;
- хардкодить результат Harness Log;
- создавать фиктивный PASS;
- привлекать субагентов;
- разбивать задачу на несколько независимых агентных вызовов.

## 24. Проверка независимости Excel и Python

Это критическое требование.

Нужно обеспечить:

```text
Python calculation implementation
≠
Excel calculation implementation
```

Они должны использовать одинаковые математические определения, но вычисляться разными механизмами.

Иначе сравнение не является проверкой.

То есть:

```text
CSV
├─→ Python calculator
│
└─→ Excel formulas

а затем:

Python result
        ↘
        Harness
        ↗
Excel result
```

**НЕ:**

```text
Python result → Excel → compare with Python result
```

## 34. Политика при неопределённости

Если сомневаешься:

1. сначала проверь PDF задания;
2. затем лекцию;
3. затем фактические CSV;
4. затем размерность;
5. затем физический и экономический смысл.

Если после этого остаётся неоднозначность:

**НЕ выдумывай решение.**

Создай запись:

```text
ASSUMPTION_REQUIRED
```

и:

- опиши проблему;
- предложи основной вариант;
- предложи альтернативу;
- оцени влияние.

Если неоднозначность **НЕ блокирует** работу — продолжай pipeline с явно указанным допущением.

Если она делает расчёт физически бессмысленным — соответствующую метрику пометь как:

```text
NOT COMPUTABLE
```

и объясни, какие данные требуются.
