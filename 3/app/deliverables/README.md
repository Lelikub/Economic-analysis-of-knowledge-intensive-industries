# Практическая работа 3, вариант Б

Запуск из `3/app`:

```powershell
..\..\.venv\Scripts\python.exe -m catalyst_risk_pipeline --data ..\data --template ..\..\end_template\Шаблон_отчета_ЭА_краткий_v2.docx --output deliverables --n 10000 --seed 314159
```

Повторный запуск перезапишет файлы внутри `deliverables`. Для проверки кода: `..\..\.venv\Scripts\python.exe -m pytest tests -q`.

Основные расчёты используют миллионы USD, дни и годовой горизонт. Каждый опыт — один годовой статус цепи и максимум один инцидент. Основной ожидаемый ущерб использует математическое ожидание логнормального времени простоя; `EL_med` — отдельный сценарий фиксированной медианной длительности. Для Парето используются исходные `alpha=1.3`, `xm=2` дня, а статус отмечает бесконечную дисперсию.

`Ground_Truth.xlsx` содержит формулы, исходные ячейки и ссылки на поля CSV. В `HARNES_LOG.xlsx` и `run_manifest.json` записан фактический статус независимого пересчёта Excel. Если Microsoft Excel COM недоступен, файл остаётся формульным, а статус `NOT_VERIFIED`; второй аналитический путь выполнен в `Decimal`.

CSV матриц содержит целевую бинарную корреляцию Пирсона. Для многомерного моделирования каждая пара калибруется в латентную нормальную корреляцию по двумерной нормальной CDF; итоговая матрица проверяется на PSD. Парный сценарий `S2` предполагает независимость остальных стадий. `S0_full` и `S2_full` используют одну базовую матрицу и seed для сравнения ROI; `S3` и `S4` — одну стресс-матрицу и seed.

Результаты: Word-отчёт, сценарная книга, журнал, `data/simulation_results.csv`, `data/historical_analysis.json`, графики, исходный код и manifest. Общий статус `PARTIAL` означает, что хотя бы одна обязательная проверка или стадия не получила `PASS`.
