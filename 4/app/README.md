# Практическая работа №4

Расчёты TCO/CBAM, оптимизация CFLP/SSCFLP через PuLP/CBC, анализ IoT и DPP,12PNG и русский Word-отчёт. Все источники читаются из `4/data` и не изменяются.

Из корня репозитория (Windows PowerShell), в существующем проектном окружении:

```powershell
.\.venv\Scripts\python.exe 4/app/main.py --data 4/data --output 4/app/output --template end_template/Шаблон_отчета_ЭА_краткий_v2.docx
.\.venv\Scripts\python.exe -m pytest 4/app/tests -q -p no:cacheprovider
```

Пайплайн сам запускает вычислительные и artifact-тесты, сохраняет исходные логи/JUnit, формирует отчёт с фактической сводкой. Затем пробует скрытый рендер Microsoft Word→PDF и проверяет реальные страницы; если COM недоступен, сохраняет честный NOT_VERIFIED для пагинации при программно проверенном DOCX. Опциональная зависимость рендера — установленный Microsoft Word и pywin32 (в текущем окружении доступны). Отдельная команда pytest повторяет проверку уже готовых результатов. Параметры по умолчанию привязаны к расположению проекта, запуск из другого каталога также допустим без явных относительных аргументов. Выходной каталог разрешён только в `4/app`.

PuLP3.3.0 установлен локально в `4/app/vendor`, подключается main.py и tests/conftest.py. Прочие библиотеки уже были в `.venv`. Для чистого окружения:

```powershell
.\.venv\Scripts\python.exe -m pip install -r 4/app/requirements.txt
```

На Windows при установке зависимостей другим пользователем могут потребоваться унаследованные права чтения/исполнения. CBC запускается последовательно (`threads=0`), gapRel0, randomSeed1, integer/primalTolerance1e-9,60с. Режим threads=1 в использованной песочнице зависал; история сохранена.

Основные результаты:

- `output/Итоговый_отчет_практическая_4_ЭА.docx` — полный отчёт и ответы1–3;
- `output/metrics.json`, `analysis.json`, `tables/` — точные результаты и данные диаграмм;
- `output/dpp_passport.json` — цифровой паспорт, реальный SHA-256 исходного CSV;
- `output/figures/`, `plot_validation.json` —12диаграмм и проверки;
- `output/test_results.json`, `report_validation.json`, `run_manifest.json` — результаты исполнения, полнота и хэши;
- `logs/execution.log`, `HARNESS_LOG.csv`, `HARNESS_LOG.md`, `cbc/` — постоянная история, трассировки и исходные журналы солвера;
- `docs/` — аудит формул, матрица требований, допущения, проблемы данных и план.

Архив RAR сверяется с первичными файлами через установленный7-Zip без распаковки на диск. Если7-Zip недоступен, первичные данные остаются основным источником; архив не нужен для расчёта.

Пределы интерпретации: CBAM с транспортом — учебная модель; GPS описывает только контрольный участок; время IoT без часового пояса; p_fail=1 после нарушения — регламент задания. Положительного ETS-порога авиа–ж/д для150–300тыс. USD/т и WACC15% нет, что подтверждено расчётом. Данные не подгоняются под предполагаемые выводы.
