# Практическая работа 4: план реализации

Цель: полностью воспроизводимый расчёт трёх модулей, проверки и русский Word-отчёт.
Спецификация: `4/task/Промт_Практическое_занятие_4_ЭА.md`, задание PDF, с. 1–10.
Пользователь делегировал технические решения и явно потребовал исполнение без остановки при спорных моментах.

Архитектура: CLI → Controller → Orchestrator → Services → типизированные объекты / calculators.
PuLP 3.3.0 + CBC; pandas, numpy, matplotlib, python-docx, pytest из проектного Python 3.14.
Изменения только в 4/app. Источники, шаблон и работы 1–3 доступны только для чтения.

1. Написать и запустить отрицательные, граничные и численные тесты до реализации.
2. Реализовать models/loaders/validators; контракт ProjectInputData, строгое чтение JSON/CSV.
3. Реализовать TCO, CBAM, линейные чувствительности, проверяемые корни и ответы 1–2.
4. Реализовать CFLP Multi/Single, Big-M MILP/LP, 3 повтора CBC, остатки и независимый перебор.
5. Реализовать IoT: интервалы 5 минут, пропуски разрывают эпизод, осевой шок, Haversine, DPP.
6. Связать стадии, независимый Harness, pytest с JUnit XML и постоянные журналы ошибок.
7. Экспортировать CSV/JSON; из сохранённых таблиц построить и проверить рисунки.
8. Заполнить Word, используя стили шаблона; проверить ZIP/XML/картинки, отрендерить при доступном движке.
9. Полный запуск; отдельный pytest; проверка неизменности источников и манифеста.

Фокус проверки: дробные y при M=1e9; отсутствие пересечений; пропуски телеметрии; NaN/строковые числа; повторный запуск и отсутствие двойного учёта ущерба.

Решения: выполняю непосредственно в текущем каталоге, поскольку пользователь ограничил результат 4/app и не просил git-операций. Установка PuLP изолирована в vendor. Шаблон сохраняет стили, служебные заполнители заменяются.
